# 뉴스 수집기 기능 개발 워크플로우

뉴스 수집기 앱에서 새 기능을 개발할 때 사용하는 명령입니다.
브랜치 생성부터 커밋, main 병합까지 전체 흐름을 안내합니다.

인자: $ARGUMENTS (새로 만들 브랜치 이름, 생략 가능)

## 실행 순서

1. **현재 상태 확인**
   - `git status`, `git branch --show-current`으로 현재 브랜치를 확인한다.
   - 현재 브랜치가 main이 아니라면 경고를 표시하고, main으로 이동할지 사용자에게 물어본다.
   - 커밋되지 않은 변경사항이 있다면 먼저 사용자에게 알리고 처리 방법을 확인한다.

2. **새 브랜치 생성**
   - `$ARGUMENTS`로 브랜치 이름이 주어졌다면 해당 이름으로 `git checkout -b` 실행.
   - 브랜치 이름이 주어지지 않았다면, 어떤 기능을 개발할 것인지 사용자에게 물어보고
     답변을 바탕으로 영어 소문자-하이픈(kebab-case) 형식의 브랜치 이름을 제안한다.
     (예: "RSS 피드 추가 기능" → `add-rss-feed`)
   - 제안한 이름을 사용자가 확인하면 브랜치를 생성한다.

3. **개발 시작 안내**
   - 브랜치 생성이 완료되면 "이제 개발을 시작하세요!"라고 안내한다.
   - 프로젝트 루트의 `CLAUDE.md`를 읽고, 이 프로젝트의 기술 스택(Next.js, Clerk, Neon Postgres,
     Drizzle, 클로드 API, Notion MCP 등)과 핵심 불변 조건(중복 판단은 원문 URL 기준,
     DB 저장은 사용자 명시적 액션에서만 발생 등)을 요약해서 다시 한번 알려준다.

4. **작업 완료 처리**
   - 사용자가 "완료" 또는 "done"이라고 입력하면:
     - `git status`, `git diff`로 변경된 파일 목록을 보여준다.
     - 변경 내용을 분석해서 커밋 메시지를 자동으로 작성해 제안한다.
     - 사용자가 커밋 메시지를 확인/승인하면 커밋을 생성한다.
     - 이후 main으로 이동하여 방금 만든 브랜치를 병합한다.

5. **병합 완료 요약**
   - 병합이 끝나면 이번 작업에서 변경된 내용을 간단히 요약해서 사용자에게 보여준다.
